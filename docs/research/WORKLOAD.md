# Finite research workload

`research_workload=bounded-research-v2` requires `research_profile=true` and an explicit control method. The immutable limits in `bin/flowdc_research_profile.py` are 32,768 original rows, 512 MiB expected original-row payload, 32 MiB metadata, 64 KiB per encoded row, 64 MiB per object, 2 GiB artifacts/worker return, four acquisition attempts, 300 seconds acquisition, and bounded clients/permits/events. New truth/study/origin/return records carry the complete profile. A profile name cannot change those limits. Legacy fixture records keep their earlier finite interpretation.

Truth counts duplicate original rows in the expected byte budget and retains the full parent denominator in partitions. Restricted metadata is checked before overwrite handling or requests. Observed HTTP bodies, including unsuccessful attempts, are read in bounded chunks and capped per downloader process at payload ceiling times attempt ceiling; this is a process limit, not a global cross-worker body-byte meter. Distributed workloads share the original truth budget and origin admission authority. Return/archive verification and collection use the explicit profile. Shared admission stores immutable scope membership separately from mutable session state and permit history.

Capacity qualification selects workload sizes using fixed concurrency only, before adaptive outcomes. Record process-tree sampled peak RSS and CPU, verification time, wall time, artifact/journal sizes, and instrumentation overhead. Sampled RSS can miss short peaks and count shared pages more than once. Calibration selects the smallest bounded workload that realizes the declared stimulus and required observations; it cannot silently enlarge a limit. A short named scenario that never reaches its scheduled change is an engineering fixture, not evidence for that condition.

Current research origin records use `flowdc-origin-scenario-v3`. Transient overload, sustained overload and recovery reduce four service slots to one at 10 seconds with a two-place FIFO queue. Capacity restores at 11 or 15 seconds for transient/recovery; sustained reduced capacity lasts through acquisition. Admitted work keeps its configured successful response. Only actual queue overflow returns 503 and Retry-After; reducing offered load can avoid rejection. Retained revision2 forced-rejection windows are historical outage diagnostics and cannot qualify this revised stimulus. Freeze and recalibrate the current definition before scientific execution.

Capture origin admission/service/response records and controller traces. Qualification requires 5–100 service starts per phase, using half its nominal service opportunities (duration × slots / maximum declared service-plus-tail delay), at least ten queue-overflow rejections spanning 80% of the declared window up to ten seconds for the fixed-client overload calibration, and the existing duration/averaging/drift gates. A later adaptive controller's avoidance of rejection is retained as an outcome, never a reason to replace its first attempt. Sparse holds remain explicit. Gradient2's 600-observation long average requires adequate observations; a delay trace that never spans its averaging behavior cannot establish that mechanism. Software tests alone do not qualify a campaign workload or demonstrate efficacy.

Native archive member lookup and verification are lazy. The outer guest transport/collection and its bounded validation child still buffer returned tar bytes; this is not a fully streaming network collection path. Legacy validation retains its 1-GiB ceiling. A 2-GiB ceiling requires the explicit research workload, checked before reading the validation body; distributed truth must name the same profile. Measure this buffering in the guest/local memory budget.

The common primary clock starts before acquisition process launch and ends after independent output verification and closed common-index readback. Preparation and VM activation are separate operational costs. Native distributed acquisition also includes staging, coordination and collection under its declared clock. Historical result files are never rewritten to appear evaluated with this profile.
