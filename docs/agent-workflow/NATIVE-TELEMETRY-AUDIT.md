`Lcn` splits only on LF, including the final empty segment after a final LF;
`h2n` removes one terminal CR. It uses TAB normally, or COLON when the tab-aware
feature flag is enabled and the returned text contains a leading tab on a line.
The Read text-result mapper applies this renderer to the native file result.
Separate prefix/suffix reminder paths exist; unsupported annotations still fail
closed rather than being stripped. Empty files and out-of-range warnings earn no
source coverage. Nine checked-in fixtures were generated by executing the extracted
pure renderer functions offline in Node, with synthetic text only. Tests need no
Node installation or native binary. They cover LF, CRLF, tabs, Unicode, empty/blank
lines, final/no-final newline and ambiguous non-LF line boundaries.

The v2 adapter accepts the numbered final empty segment only when the immutable
source really ends in LF and the requested range includes it. It earns no span.
Changed text, duplicate/out-of-range markers, unsupported annotations and ambiguous
native/inventory numbering remain incomplete. Exact Unicode text is compared
without normalization.
