# FLOW-DC review boundaries

The current package and [repository notes](../../AGENTS.md) define supported
behavior. Tests establish the exercised software behavior; scientific and cloud
claims require their own evidence.

Review configuration precedence and strict rejection, both controllers' exact
transitions, observation freshness, per-host admission, overload, Retry-After,
retry accounting, overwrite consent, original-row identity, recovery, no-follow
publication and archive verification. Distributed changes require returned-output
verification and owned-process cleanup with the qualified native runtime.

A comparative experiment needs matched manifests, hosted-byte semantics, explicit
configurations and aggregate budgets, first-attempt retention, common verification,
complete timing boundaries and unavailable outcomes. Use runs as the independent
unit and keep calibration separate from evaluation. The current manuscript inputs
remain historical observations. Software qualification cannot create new efficacy
results.

Run `make check` for a substantial change. Run native TaskVine qualification and
`make -C paper reproduce` when those subsystems change. Build a wheel and verify it
outside the checkout when packaging changes. Record exact revisions and actual
checks. Follow the [operating guide](OPERATING-GUIDE.md) for bounded independent
review, current CI and human merge.

Private records, credentials, dataset stores and machine state stay outside Git
and reviewer snapshots. Inspect the public diff for sensitive contents. Preserve
operational grants, accounting and cleanup obligations; a refactor does not
authorize activating resources or upgrading the installed supervisor.
